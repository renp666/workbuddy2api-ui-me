# 新一轮开源对标调研报告（同类热门项目，供人工拍板）

> 日期：2026-10-21 ｜ 性质：纯调研，未改任何业务代码 ｜ 前情：[2026-10-19 workbuddy 系对标报告](./2026-10-19-workbuddy通道对标调研报告.md)（#1~#14），本报告编号续接 #15 起
> 对比基线：本项目 = Go 三层（core 账号池+调度 / console 网页+九通道分流 / 八条旁路 sidecar），硬约束：Go 零第三方依赖、单机 Docker、个人账号池非多租户。

## 一、检索口径与关键事实

1. **检索范围**：本轮不再限于 workbuddy 系，改为三类同赛道热门项目：① LLM 网关/API 分发面板；② 2api/反向代理桥接；③ 账号池/凭据调度/风控对抗。共收录 **10 个项目**，其中 9 个经 GitHub API（`api.github.com/repos/*` / `search/repositories`）于 **2026-10-21** 核实星数/语言/推送时间；1 个（one-hub）多次获取失败，标注未核实。
2. **上轮已落地/已拍板项不再重复列为候选**：工具调用标记还原、余额后台刷新+解冻（有意偏差：只刷硬冷却号、不刷全池）、X-Request-Id+成功率双口径、多 API Key 归因、每日限额护栏（每日 Token + 保留积分两条先行）、IP·UA 归因、404 短冷却、粘性键哈希化等。本轮候选若与上述决策有张力，会在对应行显式说明。
3. **网络状况记录**（实事求是）：`api.github.com` 与 `www.gpt-load.com` 可达；`raw.githubusercontent.com`、`github.com` HTML 页面多次 fetch 失败（因此 README 全文获取受限，功能细节部分来自项目描述/官网文档/搜索文章，逐条标注来源）；WebSearch 有 4 次服务端报错（done-hub/one-hub/grok2api 专题搜索未全部完成）。
4. **核实口径分级**：[A]=GitHub API 核实；[B]=项目 README/官网/描述核实；[C]=搜索文章或模型常识，未逐条核实。宁可标注也不冒充。

**gpt-load 调度语义摘录**（[B] 官网 gpt-load.com 文档，2026-10-21 抓取核实）：
- 分组凭据池：加权轮转、**会话亲和**、失败重试、过热冷却、连续报错自动拉黑；凭据按状态分类统计（可用/冷却中/拉黑自动摘除）。
- 失败分类调度：**换凭据可能解决的（限流/5xx/网络超时）才重试；参数错误/模型缺失类换凭据无意义，不重试**。
- 分组级策略：模型可从上游自动发现后勾选开放，权重/超时/重试按组配置。
- 依赖：MySQL 8.2+ 与 Redis（强依赖）；支持 Master/Slave 集群。
- 对照本仓：失败分类≈`upstream.Classify`（404 不进指数退避）；会话亲和≈粘性会话；状态分类≈CoolSoft/CoolHard/CoolQuota+熔断。**同类语义本仓基本齐**。

**claude-relay-service 亮点摘录**（[B] 描述核实 + [C] 功能细节来自常识，未逐条核实代码）：
- OAuth 订阅凭据池管理、凭据到期提醒与自动刷新 [C]；多用户 API Key、用户级限流 [C]；使用统计/账号使用率仪表板 [C]；系统提示词过滤/清洗 [C]；拼车共享（多租户）[B]。

## 四、明确不建议仿照项及理由

| 特性 | 来源 | 理由 |
| --- | --- | --- |
| 多租户运营全家桶（用户体系/令牌计费/充值兑换码/分组倍率） | new-api、litellm 虚拟 key、CRS 拼车 | 本项目个人账号池非多租户，是产品定位约束不是能力缺口；引入即违反硬约束 |
| MySQL/Redis 外部依赖、Master/Slave 集群 | gpt-load、litellm proxy | 单机 Docker、零第三方依赖是硬约束；本仓文件落盘+进程内状态已满足规模 |
| 批量注册账号、风控对抗自动化（验证码/SSO 批筛） | grok-register | AGENTS.md 明确「OAuth/扫码/验证码由用户完成，不绕过验证」；号池补给侧自动化整体出局 |

| 渠道计费/缓存计费/倍率体系 | new-api | 个人自用无计费对象；价目快照（上轮 #9）已覆盖成本感知需求 |
