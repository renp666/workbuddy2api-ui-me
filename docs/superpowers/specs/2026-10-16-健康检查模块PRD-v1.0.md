## 1. 背景与目标

棱镜网关（多通道聚合代理，9 通道按模型名前缀分流）现有「通道级健康探测 + 成功调用用量账本」，但：调用报错不落账（错误只走 console log WARN，非结构化、重启即失）、探测结论不落盘（`healthHistorySize=20` 仅内存，重启丢失）、别名级错误无视图。M1 目标：**报错逐条落盘可查、探测结论重启可回放、P1 异常主动通知、错误率反哺自动选路**。

## 2. M1 范围（六项，全部必须）

### F1 错误事件账本（A1）

- 新文件 `console/errors.go`：`errorEvent` 结构，出口 handler 失败分支异步落账。
- 采集点：`/v1/chat/completions`、`/v1/messages`、`/v1/responses` 出口的错误分支（含上游非 2xx、超时、上游连接失败）；仿 `reportUsageAsync`（usage_report.go）的异步纪律——**独立协程 + 5s 上限，绝不阻塞或影响调用主链路**；落账失败保持沉默（统计是尽力而为，不是调用契约）。
- 字段（JSONL 单行）：
  ```json
  {"ts":1760582400000,"alias":"2-fast-v2","model_resolved":"qwen3.8-flash","channel":"qoder","api":"chat","mode":"stream","upstream_status":429,"category":"rate_limit","error_snippet":"rate limit exceeded, retry after 12s","duration_ms":3210,"client":"Hermes/2-fast-v2","routed_via":"qoder-proxy","retry_count":1}
  ```
  - `alias`：命中 `resolveAlias` 时填，未命中留空；`model_resolved`：剥前缀后的原生模型名。
  - `error_snippet`：截断 ≤200 字（复用/仿 `readProbeError` 逻辑），**落盘前脱敏**：不落 key/token/账号字段（沿用 usage 面脱敏口径）。
  - `client`：`clientAddress(r)` + User-Agent，与 `newUsageCapture` 同源。
- 存储：`runtime/wb2api/console/errors-<YYYYMMDD>.jsonl`，append-only，按天轮转，**保留 30 天**（启动与轮转时清理过期文件）。该目录是 bind mount，重启不丢。
- 聚合查询接口 `GET /admin/errors?window=15m|1h|24h`：按 (channel, category) 返回 {ok, fail, error_rate, top_models}，供前端区块消费。

### F2 错误归类统一口径（A2）

- 扩展现有 `probeFailureCategory()`（probe.go）为共用归类函数，**probe 与调用侧共用一份口径，禁止两张皮**：
  - 401/403→`auth`；404→`model_error`；429→`rate_limit`；408/504→`timeout`；5xx→`upstream_error`；错误体含 `pinned_account_unavailable`→`pin`；`form_error`（串味/agent 冒充）为保留值，M1 不自动打；其余→`error`。
- 保留值必须向后兼容：前端 `modelFailureLabels` 已认识的键（auth/model_error/rate_limit/error）不变。

### F3 探测结论落盘（B3）

- `healthCache.record()`（health.go）在写内存快照的同时 append `runtime/wb2api/console/health-history-<YYYYMMDD>.jsonl`（按天轮转，保留 30 天）。
- 每行一轮：`{"ts":...,"rounds":[{"channel":"qoder","public":"qoder-...","ok":true,"category":"","durationMs":..}, ...]}`（结构对齐现有 `healthRound.historyEntry()`）。
- 启动时回放最近 ≤20 轮进内存快照——验收口径：重启后 `/admin/health`（或现有健康接口）`health present: True`。

### F4 P1 告警事件（F1 前半）

- console 侧只负责**检测与落盘**：告警事件 append `runtime/wb2api/console/alerts.jsonl`（保留 30 天）+ `GET /admin/alerts`。P1 规则两条：
  1. 在用别名窗口错误率 >50% 且窗口调用样本 ≥5（15min 滚动窗口）；
  2. 任一 `pin` 类错误事件（该错误极具误导性，必须人看）。
- 抑制：同 (channel, category) 30min 内只出一条告警事件。
- **通知侧不在 console 代码范围**：由 Hermes 侧定时任务轮询 `/admin/alerts` → 看板卡 + 桌面通知（仅 P1 推送）。console 不引入任何外部通知依赖。

### F5 健康页错误统计区块（A4 后端+前端）

- 后端：F1 的 `/admin/errors` 聚合接口。
- 前端（console/web/app.js + index.html）：健康页新增「错误统计」区块——窗口错误率趋势（15m/1h/24h 三档切换）、category 分布、按通道错误数表、最近 20 条错误事件流水（snippet 可展开）。
- **触点铁律**：动 app.js 时与 `healthChannelKeys / usageChannelOrder / pageNames / showPage` 等既有锚点同批核对；`channel_consistency_test.go`（routeChannelOrder ↔ app.js usageChannelOrder 逐项比对）必须保持全绿。M1 **只加区块不加页签**。

### F6 错误率反哺自动选路（C5，2026-10-16 拍板提前至 M1）

- 接入点：`route.go` 的 `pickChainTarget()`（别名 health 策略）与 `resolveAuto()`（gateway-auto 池）。
- 设计（最小侵入）：
  - 错误率数据源：F1 账本的 15min 滚动窗口，按 (channel, 原生模型名) 聚合。
  - **防呆铁律：窗口调用样本 <5 不参与选路因子**（样本不足不降权，避免单次失败摘链）；无错误数据 = 无因子，行为与现状完全一致。
  - 样本 ≥5 且错误率 >50% 的链路：band 视为 +1 参与比较（可用→仅对话降档；band>1 本就排除）；band 相同时错误率低者优先。
  - 选路决策的 `Reason` 字段注明降权依据（如「错误率 67%（n=9），降档」）。
- 选路纪律不变：3-strong 组未经用户同意不得自动启用；priority 策略恒取链首不看因子。

## 4. 红线（违反任意一条=验收不通过）

1. **异步不阻塞主链路**：错误落账/告警检测绝不阻塞调用；失败沉默。
2. **3-strong 组禁止自动启用**；自动降级只在前面的梯队内。
3. **脱敏**：error_snippet 不含 key/token/账号。
4. **不新增第三方依赖**（go.mod 不动）；存储只用 JSONL，不建数据库。
5. **routes.json 若需改动必须串行**（saveFile 整组落盘，并发互相覆盖）；M1 预期不改 routes.json 结构。
6. **触点铁律**：channel_consistency_test 全绿；新通道/页签触点 13 处清单见 Hermes skill（M1 只加区块，预期不触发）。
7. 前后端+测试一次改齐，不留半成品。

## 5. 验收判据（全部可实测，Hermes 复跑）

1. **错误账本**：制造一次失败调用（如对不存在的模型直调）→ `runtime/wb2api/console/errors-*.jsonl` 出现一行，含 category 与 duration_ms；`/admin/errors?window=15m` 聚合数与账本行数对得上。
2. **探测落盘**：重启 console 后健康接口 `health present: True`（重启前先跑一轮探测）。
3. **告警**：注入 ≥5 次同别名失败调用使错误率 >50% → `alerts.jsonl` 出 P1 事件；30min 内同类只出一条。
4. **选路反哺**：fixture 测试——样本 <5 时选路结果与现状一致；样本 ≥5 且错误率 >50% 的链路在 `resolveAuto` 池中降档/在 `pickChainTarget` 中被同 band 低错误率者压过；`Reason` 字段含降权说明。
5. **回归**：`go test ./...` 全绿（含 channel_consistency_test、新增 errors/health/alerts 用例）；控制台健康页区块渲染正常（web_test.cjs 仿写用例）。
6. 编译：`go build ./console` 通过；不引入新依赖。
