## 〇、一句话结论

棱镜已有一套「通道级健康探测 + 成功调用用量账本」，但**调用报错不落账、探测结论不落盘、别名级健康无视图**——健康检查模块的核心增量是补齐「错误事件账本 → 归类聚类 → 根因标签 → 告警 → 方案沉淀」这条闭环，其余功能围绕它分期展开。

## 一、功能全景表

数据来源缩写：**EP**=console 主动探测（产生上游调用）、**CL**=调用链路旁路观测（零额外上游调用）、**LG**=console 服务端日志、**RT**=routes.json 配置、**UP**=上游自身接口（/health、/v1/models、配额页）。

### A. 调用侧可观测（报错面）

| 功能 | 目标 | 核心指标 | 数据来源 | 触发/采集 | 输出物 | 优先级 |
|---|---|---|---|---|---|---|
| A1 调用报错事件账本 | 调用失败不再只进 console log，逐条落盘可查 | 错误事件数、错误率 | CL | `/v1/chat/completions` 等出口失败时异步追加（仿 `reportUsageAsync`，不阻塞主链路） | `runtime/wb2api/console/errors.jsonl`（append-only + 轮转） | **必须** |
| A2 错误归类扩展 | 统一错误分类口径 | category 分布 | CL | 复用 `probeFailureCategory()` 并扩展（见 §二） | category 字段 | **必须** |
| A3 错误摘要留存 | 保留上游原始报错线索 | 摘要 ≤200 字 | CL | 复用 `readProbeError()` 的截断逻辑 | error_snippet 字段（落盘前脱敏） | **必须** |
| A4 错误聚合视图 | 看清「谁在错、错什么、错多少」 | 按别名/通道/类别的窗口错误数与错误率 | A1 聚合 | 页面加载或定时聚合 | 控制台健康页·错误统计区 | **必须** |
| A5 时延分位统计 | 识别慢模型/慢通道 | p50/p95/p99 durationMs | CL+EP | 调用与探测共用计时 | 健康页时延列 | 建议 |

## 二、已规划功能增强建议

### 2.1 「别名模型监控度检查记录」

现状实证：健康历史仅内存 20 轮（`healthHistorySize=20`），粒度是**通道 + 探测模型**，没有别名维度；watch.py 的别名轮换基线与 console 探测历史是两套数据。

| 维度 | 建议 |
|---|---|
| 字段 | `checked_at, alias, channel, model, verdict(green/red/unknown), duration_ms, category, error_snippet, consecutive_failures, last_ok_at, source(auto-seed/manual/watchdog)` |
| 指标 | 别名健康分 = 窗口内 ok/(ok+fail)，unknown 不计入分母（沿用「没测过≠测了不行」铁律）；连续失败轮数；p95 时延 |
| 展示 | 模型表加「别名健康」列（按别名聚合映射链上各目标，全绿=绿、任一红=红、未测=空）；别名检查记录表按时间倒序 |
| 落盘 | `health-history.jsonl` append-only，重启可回放；watchdog 基线与 console 记录合并为一份真源 |
| 告警 | 连续 ≥3 轮（约 90s）红灯 → P2；派单在用别名红灯 → P1 |
| 归因 | 记录里附当轮 category 与摘要，点击可跳错误聚类视图（§2.2） |

### 2.2 「模型调用报错统计」

现状实证：`usageReportEntry` 只记**成功调用**的用量（prompt/completion/credit），调用本身失败**不落账**，错误只走 console log 的 WARN 行（非结构化、重启即失、无法聚合）。

| 维度 | 建议 |
|---|---|
| 字段 | `ts, alias(若命中别名), model_resolved(剥前缀后), channel, api(chat/messages/responses), mode(sync/stream), upstream_status, category, error_snippet(≤200字), duration_ms, client(UA), routed_via, retry_count` |
| 采集点 | 出口 handler 的错误分支，异步追加（仿 `reportUsageAsync` 独立协程 + 5s 上限，绝不阻塞主链路）；与 usage 账本共用 `clientAddress()` 脱敏口径 |
| category 口径 | 扩展 `probeFailureCategory()`：401/403→auth、404→model_error、429→rate_limit、408/504→timeout、5xx→upstream_error、`pinned_account_unavailable`→pin、内容串味/agent 冒充→form_error（由形态探针确认后补打）、其余→error。**probe 与调用共用一份口径，两张皮必防** |
| 聚合 | 窗口（15min/1h/24h）× (别名， 通道， category) 三维聚合；Top-N 错误模型/通道榜 |
| 展示 | 控制台健康页新增「错误统计」区：错误率趋势线、类别分布饼图、Top-N 表、最近错误事件流水（摘要可展开） |
| 告警 | 见 §五规则表 |
| 归因 | pin 类 → 提示 corePinHint 对照；rate_limit 类 → 关联配额余量（D2）；timeout 类 → 提示按通道放宽 probeChannelTimeouts（qoder 30s 偏紧的实证教训）；form_error 类 → 引导跑 nonce 回显测试 |

## 三、新增相关功能清单（10 项以上）

1. **调用报错事件账本**（必须）：错误逐条落盘 JSONL，解决「报错无账可查、重启即失」。数据来源 CL，输出 `errors.jsonl`。
2. **探测结论落盘**（必须）：`health-history.jsonl`，解决 `/admin/probe` 结论重启丢失（实证踩过）。
3. **别名级健康分与视图**（必须）：把通道/模型探测与调用错误聚合成别名维度的健康分，解决「别名机制是日常主入口，却没有别名健康视图」。
4. **错误聚类与根因标签**（必须）：按 category+channel+摘要前缀聚类，打根因标签（auth/429/pin/串味/超时/agent 冒充），解决「报错碎片化、无法归纳」。
5. **熔断降级**（必须）：连续失败 N 轮或窗口错误率超阈，自动把别名切到 `routeEntry` 备用链或 `gateway-auto` 重选，并留 routes.json 变更留痕（`routes.bak-*` 惯例已有）。**边界：3-strong 组未经用户同意不得自动启用**（选型铁律）。
6. **配额与限流监控**（建议）：429 频次 + 各通道当日配额余量对接，解决「免费通道 50/天、2000/天等配额打满才发现」。
7. **目录漂移审计**（建议）：公布面 vs 上游 `/v1/models` 数量差定时对照 + 已下架 id 静默降级检测（实证：removed id 落回 `auto` 不报错），输出旧 id→新 id 映射建议。
8. **gateway-auto 选路反哺**（建议）：窗口错误率作选路第二输入（现仅 probeVerdict），错误多的链路自动降权。
9. **告警通知与升级**（必须）：规则命中 → Hermes 看板卡/桌面通知；P1 未确认 30min 升级 triage（对齐看板升级机制）。
10. **方案知识库闭环**（建议）：根因确认后沉淀「错误标签 → 解决方案」条目，与 `prism-gateway-channel-diagnosis` skill 的沉淀习惯对齐；同类错误二次出现直接给方案链接。
11. **时延分位统计**（建议）：p50/p95 按模型/通道，解决「4-max-v1 尾延迟 17s 误报超时」这类问题的事前识别。
12. **时段方差/降智监测**（可选）：分时段错误率与质量热力图，把「免费池傍晚降智」从经验变成数据。
13. **形态检测探针**（可选）：nonce 回显常态化为可选探测项，自动发现 agent 冒充模型通道（autoclaw 实测教训）。
14. **积分/token 异常检测**（可选）：credit 倍率偏离基线、用量突增告警，复用 usage 账本既有数据。
15. **SLA/SLO 报表**（可选）：别名可用率、MTTR、错误预算的周报。

## 四、关键指标与数据模型

### 4.1 错误事件（新增，errors.jsonl）

```json
{
  "ts": 1760582400000,
  "alias": "2-fast-v2",
  "model_resolved": "qwen3.8-flash",
  "channel": "qoder",
  "api": "chat",
  "mode": "stream",
  "upstream_status": 429,
  "category": "rate_limit",
  "error_snippet": "rate limit exceeded, retry after 12s",
  "duration_ms": 3210,
  "client": "Hermes/2-fast-v2",
  "routed_via": "qoder-proxy",
  "retry_count": 1
}
```

### 4.2 指标定义

| 指标 | 定义 | 公式 | 维度 | 采集点 | 查询示例 |
|---|---|---|---|---|---|
| error_rate | 窗口错误率 | fail/(ok+fail)，unknown 不计分母 | 别名/通道/类别 × 窗口 | A1+A4 | `python -c "统计 15min 窗口 category 计数"` |
| avail | 别名可用率 | 1 − error_rate（24h 滚动） | 别名 | A1 | SLA 报表 |
| consec_fail | 连续失败轮数 | 相邻红灯轮计数 | 通道/模型 | B1/B3 | 健康页 |
| p95_latency | 时延 95 分位 | duration_ms 排序取 95% 位 | 模型/通道 | CL+EP | 健康页时延列 |
| r429_daily | 当日 429 次数 | category=rate_limit 计数 | 通道 | A1 | 配额告警 |
| drift_gap | 目录漂移量 | 公布面条数 − 上游目录条数 | 通道 | RT+UP | 审计事件 |
| mttr | 平均恢复时长 | 红灯起点→恢复绿灯的均值 | 通道/别名 | B3 | 周报 |

### 4.3 存储

- **JSONL append-only + 按天轮转**，放 `runtime/wb2api/console/`（bind mount，重启不丢，与 routes.json 同一落盘目录）；查询用 python/jq 流式聚合，不建独立数据库。
- 理由：单实例部署（假设）、数据量小（日千级事件）、避免引入 SQLite/TSDB 的运维面；若日后事件量上百万再迁 SQLite（本仓已有 SQLite 使用先例于上游）。

## 五、告警与通知策略

### 5.1 规则示例

| 规则 | 条件 | 级别 | 抑制/聚合 |
|---|---|---|---|
| 派单别名故障 | 在用别名窗口错误率 >50% 且调用数 ≥5 | P1 | 同 (alias,category) 30min 聚合 |
| pinned 账号拦截 | 任一 pin 类错误事件 | P1 | 同通道 30min 聚合（该错误极具误导性，必须人看） |
| 通道持续红灯 | consec_fail ≥3 轮（90s）且非 seed 单点 | P2 | 同通道 60min 聚合；上游 /health 绿则降级为提示 |
| 模型消失 | drift_gap >0 或上游目录条数跌 >30% | P2 | 同通道 6h 聚合 |
| 限流抬头 | r429_daily ≥10 或环比 ×3 | P3 | 同通道 6h 聚合 |
| 配额将尽 | 余量 <20% | P3 | 每日最多 1 次 |
| 探测超时误报 | 仅 seed 轮超时、无调用错误佐证 | 不告警 | 防误报（watchdog 30s 偏紧实证） |

### 5.2 通知与升级

- 通知渠道：Hermes 看板卡（kanban_create/block）+ 桌面通知；告警事件同时落 `errors.jsonl`/事件表留痕。
- 升级机制：P1 未确认 30min → triage 列（对齐看板 unblock-loop 升级机制）；P2/P3 只留板不催。
- 抑制铁律：**探测红灯与调用错误互为佐证才升级 P1/P2**——分清「模型不在白名单 / 没命中前缀落 core / 别名解析」三条失败路径，避免把 console 侧机制问题误报成通道本体故障。

## 六、诊断与归因闭环

```
采集（A1 错误事件账本 + B3 探测历史，均落盘）
  → 归类（A2 统一 category 口径，probe/调用共用）
  → 聚类（按 category×channel×摘要前缀聚合，Top-N 榜）
  → 根因（三失败路径判定法 + corePinHint + 对照测试 + nonce 回显；
        根因标签打回事件，沉淀 prism-gateway-channel-diagnosis skill）
  → 方案（修复动作：扩白名单 / repin / 换通道 / 放宽超时 / 熔断切备用链）
  → 沉淀（routes.json 变更留痕 routes.bak-* + 知识库条目
        + 排查报告 docs/superpowers/verification/）
```

闭环关键：**每类根因绑定一个默认方案**（如 pin→对照测试后扩白名单；timeout→按通道放宽 `probeChannelTimeouts`；form_error→nonce 回显定案后走「真网关转发说明」路径），同类错误二次出现时告警直接带方案链接，形成「报错→归纳→方案」的复用。

## 九、风险、边界与待确认问题

**假设（已按此继续输出）：**
- 单实例部署、无高可用需求；数据落本机 `runtime/` bind mount。
- 期望输出粒度未指定 → 按功能分析粒度交付，PRD/技术方案待拍板后展开。
- 「监控度检查记录」按「别名模型的健康检查记录」理解（含检查历史与健康分）。

**风险与边界：**
1. 探测产生上游调用 → 免费通道 429 风控风险；沿用现有克制口径（seed 1 模型/5min、上游自带 /health 优先），错误统计零额外上游调用。

3. 前端触点 13 处同改的回归成本 → M1 只加区块不加页签；channel_consistency_test 守卫。
4. 熔断自动切链的授权边界 → 3-strong 组未经用户同意不得自动启用；自动降级只在前面的梯队内切。
5. `enabled_models` 整组落盘并发覆盖 → 熔断/自动改配置必须串行（saveFile 实证）。
