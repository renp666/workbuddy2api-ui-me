## 二、功能规格

### F3 熔断降级（C3，Q8）
- **触发**（按 (channel, 原生模型) 维度）：① 连续失败 ≥3 次（errorLedger 内连续，无成功夹隔）；② 15min 窗口错误率 >80% 且样本 ≥5。
- **动作**：命中后把该通道的该模型所在链路从选路中摘出（选路层跳过，等效 band 临时置 +N），选路自动落到同梯队备用链；`routes.json` 重写留痕：改前先拷 `routes.bak`（存在则覆盖），重写只动 active 目标、**结构与键序不变**。
- **恢复**：熔断 30min（cooldown）后自动恢复原配置（从 routes.bak 回写对应字段），恢复后该链路进入观察（下一次失败立即重新计连续失败）。
- **例外**：3-strong 组未经用户同意不得自动启用/摘除（Q3 红线不变）；pin 类（pinned_account_unavailable）不触发熔断（是账号锁不是链路故障，已有 P1 告警）。
- **留痕**：熔断/恢复各写一条 P1 告警事件（复用 M1 alerts 通道，rule=circuit_open / circuit_closed，带 alias/channel/model 与 Reason）。

### F4 429 频次计数（D2，Q9）
- errorLedger 已按归类口径把 429 记为 `rate_limit`；新增按日聚合计数：`r429_daily`（按 channel + model，当日次数），`GET /admin/errors` 聚合输出 `r429_daily` 字段；前端展示留批 M2-B。不接配额接口（Q9）。

### F5 时延分位（A5）
- usageRecord 现无 duration（实证 usage_report.go:19-29）→ `usageCaptureWriter.finish()` 补 `duration_ms`（从 capture 起始时间算，成功失败同口径；errorEvent 已有 duration_ms 不动）。
- 聚合：/admin/errors 按 (channel, model) 输出 `p50_ms`/`p95_ms`（15m/1h/24h 窗口，成功+失败混合，样本 <5 输出 null）；计算在内存聚合完成，不落新文件。
- 异步红线：duration 采集跟随现有 reportUsageAsync 协程（5 秒上限），不阻塞主链路。

### F1 别名健康视图（C1/C2，Q7）
- 模型表每行加「健康」列：口径与 M1 一致（**unknown 不计分母**）；取值 ok（错误率 <20%）/ degraded（20%–80%）/ fail（>80% 或探测连败）/ unknown（窗口无样本且无探测结论）；数据 = 24h 窗口错误聚合 + /admin/health 探测状态。
- 后端：/admin/models（或模型表数据接口）每行并入 `health` 字段（内存聚合，不新增落盘）。
- 展示：彩色徽标（绿/黄/红/灰），hover 显示错误率与样本数；不开新页签（Q7）。

### F2 Top-N 错误模型榜（A4）
- 错误统计区块内加「Top 错误模型」榜：按当前窗口错误次数全局排序前 5，显示 模型 / 通道 / 次数 / 错误率；与 /admin/errors 聚合数一致（验收对数）。

## 三、红线（继承 M1 §4，全程有效）

1. 异步落账/告警不阻塞调用主链路（独立协程 + 5 秒上限）。
2. **3-strong 组未经用户同意不得自动启用**（熔断亦不得摘除 3-strong）。
3. error_snippet 截 200 字并脱敏（不落 key/token/账号）。
4. 不新增第三方依赖（go.mod 不动）；不改 routes.json 结构与键序（熔断重写只动 active 目标，先备份 routes.bak）。
5. channel_consistency_test 保持全绿；前后端 + 测试一次改齐；gofmt tab 纪律（禁止空格重写整文件）。
6. 禁止在仓内落二进制产物；只 commit 不 push；中文 conventional 提交，只 add 自己新建/改动的文件。
7. 健康分口径铁律：unknown 不计分母（「没测过≠测了不行」）。

## 四、验收判据（可实测）

1. 熔断 fixture：注入连续 3 失败 → 选路跳过该链 + routes.bak 落盘 + P1（circuit_open）入账；注入 30min cooldown 过期 → 自动恢复 + circuit_closed；3-strong 组全程不受影响；pin 类不触发。
2. 429 计数：注入 429 → 当日 r429_daily +1 且 /admin/errors 可见。
3. 健康列：模型表健康口径与 /admin/errors + /admin/health 实测一致（unknown 不计分母，构造样本验证 ok/degraded/fail/unknown 四态）。
4. Top-N：榜上次数与 errors-*.jsonl 聚合对上。
5. p50/p95：混合样本 fixture 下分位数正确；样本 <5 输出 null。
6. `go test -count=1 ./...` 全绿 + `node console/web_test.cjs` fail 0 + `gofmt -l` 空 + go vet 干净。
