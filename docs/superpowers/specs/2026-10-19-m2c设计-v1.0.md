# m2c 批设计：熔断冷却指数退避 + 半开恢复收紧 + 摘链保护（v1.0）

> 日期：2026-10-19 ｜ 上游需求：m2c 任务书（M2-A 熔断增强收尾）
> 实现文件：`console/circuit.go`、`console/route.go`、`console/circuit_test.go`
> 验收记录：`docs/superpowers/verification/2026-10-19-m2c验收.md`

## 一、目标与不改项

熔断骨架（触发条件、错误归类、落盘回放、3-strong 禁摘）已落地，本批只补恢复策略与摘链保护：

- **不改**：触发条件（连续失败 ≥3 或 15min 错误率 >80%，样本 ≥5）、`cooldownCategory` 准入判据（rate_limit/upstream_error/timeout 才冷却）、pin 不计入、3-strong 组禁摘、熔断状态落盘 + 重启回放、`routes.bak` 机制。
- **不改**：`blocked()` 语义保持「仅 Open」——`retry_test.go` 依赖冷却到期即放行的旧语义，半开门控走新增的 `routeGate()`，两套语义并存各司其职。

## 二、冷却阶梯（任务 1）

| 连续熔断次数（Ejections） | 冷却时长 |
|---|---|
| 1 | 30s |
| 2 | 2m |
| 3 | 10m |
| ≥4（封顶） | 30m（= `circuitCooldown`） |

- 每次熔断（首熔或半开失败回熔断）`Ejections + 1` 并按上表取档；**完全恢复后归零**，下次熔断从 30s 重新起步。
- 上游 `Retry-After` 头**优先于阶梯**：有头取头值（封顶 30m），无头走阶梯。
- 阶梯为命名变量 `cooldownLadder = []time.Duration{30s, 2m, 10m, 30m}`，档位换算收敛在 `ladderCooldown(ejections)`，越界钳制到两端。
- 换算唯一入口 `retryAfterCooldown(retryAfterSec, ejections) int64`（毫秒，供 `CooldownMs` 落盘）。

## 三、状态机（任务 2：半开收紧）

```text
            连续失败≥3 或 15min 错误率>80%（样本≥5）
   ────────────────────────────────────────────────▶ ┌────────┐
   ┌────────┐   冷却到期（sweep，CooldownMs 定时）    │ 熔断态  │
   │ 健康/无状态 │ ◀──────────────────────────────  │ Open    │
   └────────┘        完全恢复（下列三条路径之一）      └────────┘
        ▲                                            │ 冷却到期
        │ 连续 2 次试探成功（ObserveOk≥2，计数归零）     ▼
        │                                      ┌───────────┐
        │         试探失败：立即回熔断且升一档        │ Observing │
        └───────────────────────────────────────│ （半开）   │
                          │                      └───────────┘
                          └────────▶ 回到熔断态（Ejections+1，重定冷却）
```

完全恢复的三条路径（都把 `Ejections`/`ObserveOk` 归零）：

1. **试探确认**：半开态连续 `observeSuccessThreshold = 2` 次成功结局（成功结局本身会释放试探租约并计数）。
2. **静默恢复兜底**：半开停留超过 `observeMaxWait = 5min` 且窗口内无失败证据——低流量目标可能等不到试探流量，防止目标被静默排除在选路与摘链目的地之外（sweep 内自动完全恢复，发 `circuit_closed` 告警）。
3. 原有重启回放：落盘状态冷却已过期的目标直接进观察态（不变）。

### 半开并发 = 1：试探租约

试探不另起探测协程——**真实请求流量即试探**。新增 `routeGate(target) bool` 挂在请求时选路（`resolveEntryChain` 逐跳过滤处，取代原先的 `blocked()` 过滤）：

- 健康 → 直通；熔断态 → 拒绝（同旧语义）。
- 观察态 → 查 `probes` 租约表：无租约（或租约超 `probeLeaseTTL = 10min` 兜底时效）则**当场认领**（记 now 时间戳）并放行；已有在途租约则本跳按不可用处理，请求走链上后续候选。同一 (channel, 原生模型) 同时最多一个在途试探。
- 任何该目标的观察结局（成功/失败）进入 `observe()` 时先释放租约；结局丢失（客户端断开等）由 sweep 按 TTL 兜底作废。
- 状态迁移全部在 `c.mu` 锁内完成（认领用写锁 + 锁内状态复查，防锁间隙并发把状态机打乱）。

### 观察态对「整批选择」的语义

新增 `unavailable(target) = blocked(target) || observing(target)`，用于两处**整批目的地选择**（不是请求时逐跳闸门）：

- 摘链改写的可用候选统计（见下节）；
- gateway-auto 候选与 fallback 摘除（`__circuit_open__` 判定）。

半开目标只收单并发试探，不做整批目的地，避免把整批流量压进半开跳。

## 四、摘链保护（任务 3）

熔断 apply 的改写分支在统计可用候选后新增判据：

- **剩余可用候选 = 1 → 禁止摘链**：不改写 routes.json（保持结构、键序与备份机制不变），只发 P1 告警 `circuit_last_candidate`（`alertLevelP1`，沿用现有告警账本与抑制机制），转人工决策。
  - 理由：坚持摘链会把全部流量压上唯一剩余候选，一旦它劣化整链皆黑；请求时选路仍会经 `routeGate` 避开本熔断跳，可用流量不中断。
- 剩余 ≥2 → 维持原摘链行为（改写 active 为首个可用候选，`routes.bak` + 意图落盘 + 重启回放不变）。
- 3-strong 组禁摘、`circuitProtected` 判据、`originalEntry` 还原逻辑均不变。

## 五、常量表

| 常量 | 值 | 含义 |
|---|---|---|
| `cooldownLadder` | `[]{30s, 2m, 10m, 30m}` | 冷却阶梯，按 `Ejections` 取档 |
| `circuitCooldown` | 30m | 阶梯封顶值（沿用原常量）；Retry-After 封顶 |
| `observeSuccessThreshold` | 2 | 半开连续试探成功阈值 |
| `probeLeaseTTL` | 10min | 试探租约兜底时效 |
| `observeMaxWait` | 5min | 半开静默自动恢复窗口 |
| 熔断触发（不变） | 连败≥3 或 15min>80%（n≥5） | 沿用 M2 拍板 |

落盘新增字段（`circuits-*.jsonl`，向后兼容：旧记录缺字段按零值处理，冷却回落 `circuitCooldown`）：

| 字段 | 含义 |
|---|---|
| `ejections` | 当前恢复周期内连续熔断次数 |
| `observe_ok` | 半开态连续试探成功计数 |

## 六、告警

| rule | 级别 | 时机 |
|---|---|---|
| `circuit_open` | P1 | 熔断（不变），message 含阶梯档位冷却时长 |
| `circuit_closed` | P1 | 冷却到期进观察态（「进入试探观察」）与完全恢复（「试探恢复确认」/静默恢复） |
| `circuit_last_candidate` | P1 | 新增：候选池仅剩 1 个可用候选时禁摘转人工 |
