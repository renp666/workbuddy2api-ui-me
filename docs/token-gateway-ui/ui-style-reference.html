Token Gateway UI Reference Board

Token 转发网关控制台
6 种可落地的界面风格

每一种风格都用你真实的控制台信息架构（侧边栏 + 4 个核心 KPI + 用量曲线 + 渠道状态表）画了等比示意图，而不是网上随便找的截图。看完挑一个，再往下翻参考站点清单和设计原则。

MOST POPULAR
深色克制 · Linear 风
开发者工具标配，暗色优先，低对比边框，一个强调色。长时间盯屏不累，信息密度高却不吵。
BEST FOR DATA
明亮金融 · Stripe 风
表格即主界面，数字右对齐用等宽数字，精确到分。适合账单/token 计费这类要建立信任的场景。
MOST RESTRAINED
纯黑白 · Vercel 风
几乎无装饰，层级全靠间距和字重。绿/黄/红只用来表示状态，一眼就抓到出问题的渠道。
MOST MODERN
毛玻璃 · Aurora 风
渐变光晕 + 半透明卡片 + 悬浮层次。视觉上最"贵"，但要控制好性能和信息密度。
STYLE 01

深色克制 · Linear 风

目前开发者控制台的事实标准。暗色优先设计，浅色模式是补充。边框极低对比，靠字重和间距建立层级，颜色只用来表达状态。适合你的用户是天天泡在里面的开发者。

RULES

不管选哪种风格都成立的 8 条

风格可以抄，但这几条是让界面"专业"和"业余"的分水岭。2026 年的共识：渐进披露是最重要的模式——先给出回答"一切还好吗？"的那一个数字，其他按需下钻。

01

主视图最多 7–8 个元素

顶部 3–5 个核心 KPI 打头阵，次要信息全部推到 Tab / 下钻 / "查看全部"后面。堆满的仪表盘一周内就没人看了。

02

颜色只表达状态

红=故障、绿=正常、黄=降级。不要用颜色做装饰，一旦某个色块不承担语义，用户就会学会忽略它。

03

数字必须用等宽数字

font-variant-numeric: tabular-nums。这是成本/流量类界面最容易忽略却最影响专业感的一行 CSS。

04

空白分组，不用边框分组

相关项靠间距聚在一起。满屏框线等于没有层级，视觉噪音直接拉低可信度。

05

暗色优先设计

开发者工具、AI 工具、监控产品现在都是暗色先行、浅色补充。你的用户一天要盯 6 小时，深色是刚需。

06

空状态占 80% 的"完成感"

大多数模板零个空状态设计。新渠道 0 条时说什么？令牌 0 个时引导做什么？这块比主界面更决定第一印象。

07

设计系统要统一

shadcn 生态的最大优势是互操作——任何模板的组件都能混用，因为你站在同一套 Radix + Tailwind 基础上。

08

键盘优先 + 快捷键可发现

像 Linear 那样按 ? 出快捷键面板。你的管理员一天点几百次表格，省下的秒数是可观的。

ACTION

照着做的落地顺序

风格定下来之后，按这个顺序改，不要一上来就重写全部页面。

先定设计令牌，再动页面

在 globals.css 里定 8 个变量：--bg --surface --border --fg --muted --accent --ok --err。所有组件只引用变量不写死颜色，这样换主题 = 改 8 行。

用 shadcn/ui 打地基

初始化后先只装这几个：button card table input select dialog tabs dropdown-menu tooltip sonner badge dropdown。它们能覆盖控制台 80% 的场景。不要一次装 50 个，用不上的组件是负债。

重构侧边栏 + 顶栏骨架

这一步收益最大：把侧栏定宽 240–260px，按"概览 / 管理 / 账务 / 系统"四组重新归类菜单。加分组标签。顶栏放全局时间范围选择器（很多控制台都缺这个）。

重做仪表盘信息层级

按 Stripe 的公式：240–280px 侧栏 + 4–6 个 KPI 卡横条 + 下方 12 列栅格放图表和表。KPI 卡必须带 delta（较昨日/上周涨跌），没有对比的数字没有信息量。

把表格当作一等公民

令牌列表、调用日志、渠道列表——这三页是用户停留时间最久的。用 TanStack Table 虚拟滚动，列宽可调、列可排序、筛选存到 URL。行悬停显示快捷操作按钮（编辑/禁用/复制）。

补空状态 + 加载态 + 错误态

三种状态每页都要有。空状态给"下一步该做什么"的按钮；加载态用骨架屏而不是转圈（尤其表格）；错误态要说人话并给重试。这块做好的感知提升比换配色大得多。

最后加动效，只加两种

① 数值变化时的滚动过渡（Ramp 那种，数字跳动很提神）；② 状态切换的过渡。控制在 150–250ms，用 ease-out。不要入场动画、不要视差滚动，控制台不需要。

接上真实数据再调一次

务必在表格填满真实数据的状态下再看一遍设计。很多截图里好看的界面，塞进 200 行数据后就崩了——列宽不够、状态色刷屏、数字撑破卡片。这一步必须做。
