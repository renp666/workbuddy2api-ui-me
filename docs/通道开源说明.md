# 通道开源说明

本文件记录本仓 7 条上游通道的**源代码来源**、**技术方案开源出处**与**更新获取方式**，供后续 agent 追踪上游更新或改造思路使用。

## 怎么用这份文档

- **先看权威来源，再看本文件。** 版本号、commit、镜像 tag 一律以仓库内文件为准，本文件只做指路，不写死版本：
  - `upstream.lock` —— core（workbuddy）通道的上游 commit 与源码摘要。
  - `docker-compose.yml` 与 `deploy/compose.<通道>.yml` —— 各旁路通道的镜像/构建与端口。
  - `deploy/<通道>.Dockerfile` —— 外部引用型通道的源码拉取地址。
  - `AGENTS.md` —— 三层血缘与「能改哪一层」的边界。
- **要「获取更新」**：按第 5 节「更新操作手册」逐类执行。
- **要「改造思路」**：看每条通道的「改造入口」小节，以及第 6 节「候选/参考实现」。

## 1. 三层血缘（决定改哪一层）

| 层 | 仓库 | 职责 |

| ① 原作者 | `https://github.com/Sliverkiss/workbuddy2api` | 账号池、调度器、上游客户端、WAF/IP 级防护 |

## 3. 逐通道来源详解

### 3.1 workbuddy（core 固定上游）

- **上游仓库**：`https://github.com/Sliverkiss/workbuddy2api`（commit 与源码摘要见 `upstream.lock`）。
- **License**：MIT（`LICENSE`，Copyright (c) 2026 Sliverkiss）。
- **本仓形态**：`upstream/` 是上游**历史快照**，不等于原作者当前 `master`；本仓改动通过 `extensions/`（新文件）与 `patches/`（改上游既有文件）叠加，`scripts/overlay.py prepare` 物化。
- **技术栈**：Go。
- **改造入口**：账号池/调度/上游客户端改动一律走 `patches/`（附 `patches/README.md` 的修改原因与移除条件）；新增能力放 `extensions/`。
- **更新方式**：见第 5.1 节。

### 3.2 zcode（GLM 编码套餐）

- **上游服务**：智谱 GLM 编码套餐（国内 `bigmodel` / 国际 `zai`）。
- **源码/镜像来源**：`https://github.com/TriDefender/zcode-proxy`；本仓直接使用其**预构建镜像**（`deploy/compose.zcode.yml` 的 `image` 字段）。
- **License**：本仓未记录，接入前需自行核实。
- **技术栈**：TypeScript / Bun；`command: ["bun", "run", "src/index.ts", "android"]` 让进程常驻。
- **端口/卷**：代理 `8080`、控制 `9090`、凭据与配置落 `/data`（宿主 `runtime/zcode/`）。
- **本仓改动**：无源码级改动，仅 overlay + `console/zcode.go`（分流）+ `console/zcodecontrol.go`（页签控制链路）+ `deploy/zcode.config.yaml`（模板）。
- **改造入口**：换镜像 tag 升级；页签支持登录/启停/档位切换（`coding-plan` / `start-plan`）。
- **更新方式**：见第 5.2 节。

### 3.3 qoder（Qoder 国内版）

- **上游服务**：Qoder 国内版；登录有两条路径——**设备码 OAuth 页面登录**（推荐）或 `WB2A_QODER_PAT` 无人值守。
- **源码来源**：`https://github.com/avaritiachaos/qoder-proxy`（`deploy/qoder.Dockerfile` 内 `git clone --depth 1`）+ npm 包 `@qodercn-ai/qoderclicn`。
- **License**：本仓未记录，接入前需自行核实。
- **技术栈**：Node.js（`node:20-alpine`）。
- **端口**：数据面 `3000`（`PORT`）、登录控制面 `3001`（`CONTROL_PORT`），均只监听 `127.0.0.1`。
- **本仓改动（构建期补丁 + 控制进程，均在 `deploy/`）**：
  - `qoder-relax-token-guard.cjs` —— 放开上游对 PAT 环境变量的硬性 401。
  - `qoder-fix-e2big-argv.cjs` —— 修 Linux 下超长 `--append-system-prompt` 触发的 `spawn E2BIG`。
  - `qoder-login-ctl.cjs` —— **本仓自建**控制进程（非上游组件）：驱动 `qoderclicn` 设备码 OAuth，暴露 `/login/start`、`/login`、`/logout`、`/status`，console 经 `WB2A_QODER_CONTROL_URL` 调用。
- **控制链路**：`console/qodercontrol.go` 提供 `/admin/qoder/login`（POST 发起 / GET 轮询）、`/admin/qoder/logout`；`WB2A_QODER_CONTROL_URL` 未配置时页签退化为纯 PAT / 只读模式。
- **改造入口**：PAT 由 `WB2A_QODER_PAT` 注入；页签含登录/登出 + 状态 + 模型 + 对话测试。
- **更新方式**：见第 5.3 节。

> 注：`AGENTS.md` 第 34 行仍写「qoder-proxy 无控制面/OAuth/生命周期」，与 `bae3a44` 之后的实际代码不符，以本节与代码为准。

### 3.4 opencode（OpenCode Zen 免费模型）

- **上游服务**：OpenCode Zen 免费模型（`opencode/*` 系列）。
- **源码来源**：`https://github.com/louchi1984-coder/ow-bridge`（`deploy/opencode.Dockerfile` 内 `git clone --depth 1`）。
- **License**：本仓未记录，接入前需自行核实。
- **技术栈**：Node.js；**基础镜像必须 Debian（glibc）**——OW Bridge 首启下载的 opencode 官方二进制是 Bun 编译，musl/alpine 跑不动。
- **端口/卷**：`41980`，数据落 `/data`（宿主 `runtime/opencode/`）；`BUDDY_NO_SYNC=1` 关闭反向写 WorkBuddy 配置。
- **硬约束**：全部路由要求 `Authorization: Bearer`；任何带 `Origin` 头的请求一律 403 → 代理必须 `Del("Origin")` 并注入 Bearer（entrypoint 与 console 共享密钥文件）。
- **本仓改动**：overlay + `deploy/opencode-entrypoint.sh` + `console/opencode.go`（分流 + 只读状态透传）。
- **改造入口**：页签只读（透传 OW Bridge `/health` 的 phase/版本/模型探测分级）。
- **更新方式**：见第 5.3 节。

### 3.5 autoclaw（AutoClaw 免费模型）

- **上游服务**：`https://autoclaw.z.ai/`（国内 `autoglm-acceleration-api.zhipuai.cn` / 国际 `autoglm-api.autoglm.ai`）。
- **源码来源**：**本仓自持** `deploy/autoclaw2api/`（`bridge.py` + `check.py` + `console.html` + `config.json`），Python 自研桥接。
- **License**：参考实现来源需核实；技术方案完整说明见 `deploy/autoclaw2api/README.upstream.md`。
- **技术栈**：Python 3.10+（`bridge.py` 依赖 `httpx` + `websockets`；`check.py` 纯标准库）；镜像 `python:3.12-slim`。
- **端口/卷**：`7865`，数据落 `/data`（宿主 `runtime/autoclaw/`）。
- **形态**：**完整控制链路**——国内版手机号+短信验证码登录、国际版 OAuth 回调导入、账号启停/删除、积分刷新、维护与逐账号签到。
- **接口边界**：数据面**只实现 OpenAI `/v1/chat/completions`**，不支持 Anthropic `/v1/messages`。
- **改造入口**：`bridge.py` 内的账号池/状态机/调度；模型清单为逆向快照（见 `README.upstream.md`）。
- **更新方式**：见第 5.4 节。

### 3.6 trae（Trae SOLO 免费模型）

- **上游服务**：Trae SOLO（`trae.cn`）。
- **源码来源**：**本仓自持** `deploy/trae2api/`（纯 Go，模块 `workbuddy2api-trae`）；源码**移植自参考实现 AgentPoints 的 `internal/trae/`（MIT）**，入口壳为本仓自写（见 `deploy/trae.Dockerfile` 头部注释）。
- **License**：参考实现 AgentPoints 为 MIT；本仓构建时 `COPY LICENSE /app/LICENSE`。
- **技术栈**：Go 1.23 构建 + `alpine:3.20` 运行；零第三方依赖。
- **端口/卷**：`7866`，数据落 `/data`（宿主 `runtime/trae/`）；`TRAE_CALLBACK_LISTEN=0`（回调由 console 承接）。
- **形态**：**完整控制链路**——OAuth 登录（回调落 console 公开 `GET /authorize`，因 trae.cn 授权页对 `auth_callback_url` 做 SSR 形状校验，主机须为字面量 `127.0.0.1`、路径须为 `/authorize`）、凭据导入、账号启停/删除/刷新、积分、排程、用量。
- **接口边界**：只生成 OpenAI 协议示例，不支持 Anthropic `/v1/messages`。
- **改造入口**：`deploy/trae2api/trae/{auth,pool,scheduler,server,upstream}/`；控制链路用标准 HTTP 状态码表达业务结果（400/404/409 原样透传）。
- **更新方式**：见第 5.4 节。

### 3.7 raccoon（小浣熊免费模型）

- **上游服务**：小浣熊（`xiaohuanxiong.com`）。
- **源码来源**：**本仓自持** `deploy/raccoon2api/`（纯 Go，模块 `workbuddy2api-raccoon`）；**上游协议口径来自 `https://github.com/aimod-cc/agent2api` 的 raccoon provider**（见 `deploy/raccoon2api/main.go` 与 `raccoon/auth/auth.go` 头部注释）。
- **License**：参考实现 `aimod-cc/agent2api` = **MIT + 使用声明限制（禁商用 / 禁二次分发牟利 / 禁批量账号运营），非纯 MIT**；本仓自建 Dockerfile，构建时 `COPY LICENSE /app/LICENSE`。
- **技术栈**：Go 1.22.5，零第三方依赖；镜像 `alpine:3.20`。
- **端口/卷**：`7867`，数据落 `/data`（宿主 `runtime/raccoon/`）。
- **形态**：**完整控制链路**，登录环节 = **凭证导入**（桌面登录态依赖宿主 DPAPI，容器内读不到；凭证文件 `~/.box-agent/config/auth.json`）；每日积分以账单核对为权威结果，无原生签到。
- **接口边界**：只生成 OpenAI 协议示例，不支持 Anthropic `/v1/messages`。
- **改造入口**：`deploy/raccoon2api/raccoon/{auth,pool,scheduler,server,upstream}/`。
- **更新方式**：见第 5.4 节。

## 4. 两类源码的纪律

| 类型 | 通道 | 纪律 |
| --- | --- | --- |
| **外部引用** | zcode、qoder、opencode | 源码不在本仓；升级 = 改镜像 tag / 重新 clone。本仓补丁必须显式登记在 Dockerfile 与本节，并注明来源与 License。 |
| **仓内自持** | autoclaw、trae、raccoon | 源码在本仓 `deploy/<通道>2api/`；直接改本仓源码，构建时 `go test ./...` / `python` 测试随镜像构建执行。 |

**共同硬约束**（来自 `docs/superpowers/plans/2026-10-08-channel-expansion-plan.md` §3.3）：

1. **禁止把第三方多通道网关整体当 sidecar 引入**——会带进它自带的其它通道，破坏「一通道一前缀」命名空间纪律；用其代码必须**只抽取目标单通道**。
2. **自建 Dockerfile 而非直接依赖第三方镜像**（尤其 MIT+限制、非标准 License 的实现有合规风险）；代码引用须在交付说明标注来源与 License。
3. **登录能力受限于容器环境**——容器内不可用的登录态（DPAPI、Windows 客户端）一律退化为「凭证导入」或「人工 noVNC 登录」，不假设有网页登录。

## 5. 更新操作手册

### 5.1 core（workbuddy）上游更新

仅在明确授权后执行；构建相关目录须无未提交改动，显式指定 commit 或 tag：

```bash
python3 scripts/overlay.py update --ref COMMIT_OR_TAG
git diff -- upstream upstream.lock
git diff -- patches extensions deploy console scripts
```

脚本在候选目录验证补丁、扩展、测试及隔离容器验收，成功才更新快照和锁文件。失败保留诊断候选，不自动提交/推送/发布/重启。

### 5.2 zcode 镜像更新

1. 查 `https://github.com/TriDefender/zcode-proxy` 的 release / tag。
2. 改 `deploy/compose.zcode.yml` 的 `image` tag。
3. `docker compose -f docker-compose.yml -f deploy/compose.zcode.yml up -d` 拉新镜像并重启。
4. 注意：`ZCODE_PROXY_CREDENTIAL_SECRET` 一旦设置必须保持不变，否则旧凭据无法解密。

### 5.3 外部引用源码更新（qoder / opencode）

- 源码在 Dockerfile 内 `git clone --depth 1`，**默认跟随上游默认分支**。要锁定或升级版本，需在 Dockerfile 中显式指定 `--branch <tag>`。
- 升级后重新构建镜像并**逐一核对本仓补丁是否仍能应用**（qoder 的两个 `.cjs` 补丁基于上游文本，上游改动可能导致补丁失效）。
- 参考 `deploy/compose.qoder.yml` / `deploy/compose.opencode.yml` 的 `build:` 段。

### 5.4 仓内自持源码更新（autoclaw / trae / raccoon）

- 直接改 `deploy/<通道>2api/` 源码，改完按 `docker-compose.build.yaml` 或对应 overlay 重建镜像。
- **上游协议变更**：autoclaw/trae/raccoon 的上游是逆向协议（非官方 API），上游改版会静默破坏解析。发现通道异常时，先对照上游行为核对 `upstream/` 或 `constants.go` 的端点与字段口径。
- 对照 `deploy/trae.Dockerfile` / `deploy/raccoon.Dockerfile` 的 `go test ./...` 与 `deploy/autoclaw2api/test_bridge.py` 保证回归。

## 7. 合规与授权边界

- 各上游服务的可用性、额度和模型行为由其自身决定，**本仓未对任何旁路通道做真实上游验收**。
- 登录、扫码、验证码、地区选择由用户本人完成，程序不绕过验证或激活。
- 第三方参考实现的 License 必须在交付说明中标注（agent2api = MIT+限制、loomy2api = 非标准开源）；**接入前先核实，不得默认按 MIT 处理**。
- 更新上游、发布镜像、推送 Git、重启实际服务分别需要对应授权；发布镜像不等于部署授权。
